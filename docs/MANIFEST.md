# manifest v1（登録マニフェスト）

TuiPWA が登録アプリ 1 件を表す JSON です。Web App Manifest とは互換ではありません。登録コマンドの使い方は [README](../README.md#使い方)を参照してください。

[例](../examples/nano.json):

```json
{
  "schemaVersion": 1,
  "id": "nano",
  "name": "nano",
  "title": "nano — TuiPWA Native",
  "mode": "native",
  "command": "nano",
  "arguments": [],
  "workingDirectory": "."
}
```

| フィールド | 仕様 |
|---|---|
| schemaVersion | 必須、整数 1 |
| id | 必須、小文字英数字で始まる `[a-z0-9._-]`。登録キー・ファイル名になります |
| name | 必須、デスクトップメニュー表示名 |
| icon | 省略可能です。存在する PNG / ICO のパスです。SVG・テーマアイコン名は対象外 |
| title | 省略時 name。端末内 OSC タイトルでは上書きしません |
| mode | 必須、`native` のみ。他のモードはエラー |
| command | 必須、実行ファイルパスまたは PATH 上の名前 |
| arguments | 省略時 `[]`。文字列配列。空文字・空白・引用符をそのまま argv として渡します |
| workingDirectory | 省略時マニフェストの親ディレクトリ。存在するディレクトリ |

- UTF-8 JSON で、キーは camelCase です。未知のフィールド、型違い、不正 JSON、null の必須フィールドは拒否します。
- 名前・タイトル・コマンド・パスは空白のみと制御文字を禁止します。引数は NUL と null を禁止します。
- パスの相対基準は**マニフェストの親ディレクトリ**です。登録時に絶対パス化してコピーします。`command` は `/` を含むとパス、含まないと起動時 PATH 検索です。`~`・環境変数・glob を展開しません。
- コマンドの存在や実行可能性は起動時に PTY が検査します。登録は将来利用するコマンド名も受け付けます。アイコンは登録時に存在と拡張子を検査します。登録済みアイコンのファイルが失われても、`run`・`list`・`show`・`remove` は利用できます。
- マニフェストはコード実行の許可そのものであり、サンドボックスではありません。信頼できないものを登録しないでください。自動でシェル文字列に連結しません。シェルが必要なら `/bin/sh` と `["-c", "..."]` を明示します。

## 登録契約

- 保存先: `${XDG_CONFIG_HOME:-~/.config}/tuipwa/apps/<id>.json`
- デスクトップエントリ: `${XDG_DATA_HOME:-~/.local/share}/applications/tuipwa-<id>.desktop`
- XDG 変数は絶対パスだけ採用します。ユーザー領域のみを変更し、sudo は不要です。
- `.desktop` には `Type=Application`・`Name`・`Icon`（任意）・`Exec`・`Terminal=false` を設定します。`Exec` は絶対パスの `tuipwa run <id>` です。空白・引用符・バックスラッシュ等を Desktop Entry 仕様の二段階でエスケープし、`%` は `%%` とします。シェルを介しません。
- 同じ ID / エントリの上書きは禁止です。変更は `update`、または `remove` → `add` で行います。ID の変更はできません。
- 登録失敗時は新規マニフェストとエントリをロールバックし、既存エントリは保持します。
- 登録解除ではマニフェスト・対応するエントリ・メタデータと、TuiPWA が所有する生成アイコンを削除します。外部で置換されたエントリは削除を拒否します（所有者は `X-TuiPWA-Id=` で確認）。実行中セッション・ユーザー指定画像・システムアイコンは削除しません。
- `.desktop` は登録時の CLI の絶対パスを保持します。`make install` 後の CLI、または固定した手動配置先から登録してください。CLI を移動・削除すると既存エントリは起動できなくなります。

## 追加メタデータ

生成アイコンの実体パスは `icon` に記録します。再生成用の追加情報（設定方式・色・参照先）とカテゴリは `tuipwa/meta/<id>.json` に分離し、manifest v1 自体には追加しません。メタデータがない登録も読み込め、カテゴリがない場合は `Utility` として扱います。

起動・終了の内部処理は [開発ガイド](../CONTRIBUTING.md#責務プロトコル)、アイコンの指定方法は [README](../README.md#アイコンカテゴリを指定)を参照してください。
